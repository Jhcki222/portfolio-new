# 프로젝트 상세 원고 작성 근거

## 자료와 편집 기준

- 사용자 제공 `C:/resume-agent/self_intro_agent/EXPERIENCE_BANK.md`의 프로젝트별 경험 카드.
- `docs/knowwhohow`, `docs/collabo`, `docs/paper`의 화면·아키텍처 이미지.
- 사용자 첨부 `pasted-text.txt`의 작성 방향: 문제·원인·판단·구현·검증·결과가 드러나는 사례, 개인 역할 구분, 근거 없는 숫자 금지.
- 기존 `src/data/portfolio.ts`의 졸업 프로젝트 기간과 기존 프로젝트의 공개 링크.

원고는 `src/data/project-details/`에 보관합니다. 실제 수행 사례와 결과를 중심으로 쓰며, 모든 프로젝트에 동일한 분량이나 문제 개수를 강제하지 않습니다. 실제 소스 코드가 제공되지 않아 예시 코드를 경험 코드처럼 작성하지 않았습니다. 미확인 역할·기간·팀 규모·사용자 반응·실험 조건도 추가하지 않았습니다.

## 공개 이미지

선택한 원본만 `public/projects/<slug>/`로 복사하고 본문 캡션과 대체 텍스트를 제공합니다. 원본 `docs/`와 경험 카드 전체를 공개 자산으로 복사하지 않습니다.

- KnowWhoHow: 서비스 표지, 온프레미스·AWS 구성도, 실제 추천 결과 화면, 상품 ETL DAG. 사용자 제공 PNG의 원본 크기와 비율을 보존합니다.
- COLLABO: 메인 화면, 최종 아키텍처, 추천 화면, QA 생성·적재 흐름.
- Pixel art: 논문 알고리즘, 게재 논문 첫 페이지.

## 추가 확인할 정보

- Delishare 폴더는 비어 있어 경험 카드만 사용했습니다. 별도 화면·저장소 링크·개발 기간은 미확인입니다.
- KnowWhoHow의 클라우드 이관·서버 이중화는 장애 이후 제안한 과제이며 완료한 결과로 쓰지 않습니다. 마이데이터는 실제 금융기관 운영이 아닌 모의 구현입니다.

## 문장 편집

[Humanizer v2.11.2](https://github.com/blader/humanizer/blob/main/SKILL.md)의 지침을 적용합니다. 역할과 기술적 판단, 수치는 보존하고, 반복되는 소개와 소감·불필요한 부정문을 줄입니다. 포트폴리오의 전후 비교는 문제 해결을 설명하는 데 필요하므로 유지합니다. 근거 없는 기능·성과·개인 경험은 문체를 자연스럽게 만들기 위해 추가하지 않습니다.

## 추가 반영 자료

노후하우의 DB 이중화는 경험 카드에 확인된 MySQL Master/Slave·HAProxy 구성과 AbstractRoutingDataSource·LazyConnectionDataSourceProxy의 readOnly 기반 라우팅을 설명합니다. 자동 장애 전환이나 무중단 검증을 새로 주장하지 않습니다. 모의 마이데이터는 표준 API 명세를 참고해 직접 구성한 메인·인증·리소스 서버 환경임을 명시합니다.
