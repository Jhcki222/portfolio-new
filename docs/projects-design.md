# Projects 디자인 노트

## 목적과 범위

채용 담당자가 프로젝트의 목적과 기술을 빠르게 파악하고 개별 소개를 읽을 수 있는 포트폴리오입니다. 메인 페이지의 섹션 구조와 기존 콘텐츠를 유지하면서 Projects의 폴더 형태를 가로형 목록으로 교체했습니다.

노후하우와 COLLABO는 실제 서비스 화면과 소개를 두 열로 배치합니다. 나머지 프로젝트는 이름·설명·상세 링크를 한 줄에 두고, 모바일에서는 설명을 다음 줄로 내립니다. 항목 전체를 하나의 내부 링크로 만들어 이미지와 제목 어디에서든 상세 페이지로 이동할 수 있습니다.

## 시각 기준

- 목록 배경 `#f7f9fb`, 제목 `#18232d`, 본문 `#54616e`, 강조 `#285c85`.
- 상세 배경 `#f8f9fb`, 제목 `#111113`, 본문 `#505b68`, 강조 `#215d97`.
- 기존 무채색과 옅은 파란색을 이어갑니다. 상세 본문은 문서처럼 읽기 쉬운 밝은 면을 사용합니다.
- 한국어 제목·본문은 로컬 Pretendard Variable, 줄바꿈은 `keep-all`과 넘침 방지를 적용합니다.
- 본문 16~17px, 줄 간격 1.9~1.95. 상세는 206px 목차와 나머지 본문으로 분리해 아키텍처도 읽을 수 있는 폭을 확보합니다. 태그는 12px입니다.
- 목록에서는 원형 화살표와 기술 배지를 없애고 여백과 구분선으로 항목을 나눕니다. 상단 미리보기는 원본 비율을 유지해 보여주며, 기술은 핵심 네 개까지 텍스트로 표시합니다. 상세는 역할·링크를 상단에, 실제 서비스 화면과 설계 이미지를 본문에 배치합니다.
- 디자인 변화 5, 움직임 2, 정보 밀도 3. 애니메이션은 링크의 반응을 알려 주는 짧은 효과로 한정합니다.

## 컴포넌트와 접근성

- `ProjectListItem`: 프로젝트 이름과 ‘소개 보기’를 접근 가능한 이름으로 갖는 단일 `Link`입니다. 내부에 다른 링크·버튼을 중첩하지 않습니다.
- `ProjectTags`: 목록과 상세에서 동일한 기술·분야를 표시합니다.
- `ProjectDetail`: 역할·기간·링크, 목차, 개요·기여·설계·사례와 다음 프로젝트 탐색을 조합합니다.
- `ProjectChapter`: 사례별 소제목·단락과 접근 가능한 성과 비교 표를 렌더링합니다.
- `ProjectFigure`: `next/image`의 원본 비율, 반응형 크기, 설명과 새 탭 원본 보기를 제공합니다. 논문 이미지는 세로 비율로 보존합니다.
- 프로젝트 데이터는 서버 컴포넌트에서 렌더링합니다. 상세 페이지별 제목과 설명을 생성합니다.
- 1100px 이하에서는 목차를 본문 위에 배치하고, 700px 이하에서는 제목·역할과 동작 흐름도 한 열로 배치합니다.
- 링크 포커스를 명확하게 표시하며 `prefers-reduced-motion`에서는 이동 효과를 끕니다. 주요 링크는 44px 이상의 터치 영역을 가집니다.
- 외부 링크의 새 탭 동작을 스크린 리더에 알리고, 모든 상세 페이지에 목록 복귀 경로를 제공합니다.
- 성과 수치·기간·팀 규모를 새로 만들지 않습니다. 원고는 제공된 경험 카드와 화면·설계 자료에 근거하며, 기존 Experience의 COLLABO 기간을 재사용합니다. 개인 기여와 팀 서비스의 전체 구성을 구분합니다.

## 검증 기준

- 메인 Projects의 각 링크가 해당 소개 페이지를 엽니다.
- 6개 상세 주소가 요청한 순서로 표시되고, 삭제된 TravelBox·LocalMark와 알 수 없는 주소는 404를 반환합니다.
- 목차의 모든 대상 ID가 한 번씩 존재하고, 원본 이미지 링크가 이미지 응답을 반환합니다.
- `/projects`는 기존처럼 메인 페이지의 Projects 섹션으로 연결됩니다.
- 모바일 가로 넘침 없이 모든 내용을 읽고 링크를 사용할 수 있습니다.
- 상세 페이지에서 헤더의 Projects 표시와 목록 복귀가 동작합니다.
- 목록을 스크롤한 뒤 같은 Projects 메뉴를 다시 눌러도 해당 섹션으로 이동합니다. 모바일에서도 프로젝트 링크의 접근성 이름에 ‘소개 보기’가 유지됩니다.
- ESLint, 타입 검사, 프로덕션 빌드 및 실제 HTTP 경로 테스트를 통과합니다.

## 첫 화면

사용자 요청으로 중앙 정렬 인사말·옅은 파란 배경·프로젝트와 연락 버튼·커맨드 입력창이 있는 이전 화면으로 복원했습니다. 첫 화면의 시각 스타일은 `src/app/hero.css`, 키워드 이동은 `CommandBar`에서 관리합니다.

## 노후하우 본문 순서

모의 마이데이터 환경 구성·DB 이중화 → AI 금융상품 추천 → 반복 DB 조회 개선 → 설계와 동작 흐름 순으로 배치합니다. `architecture.placement`로 설계 영역의 위치를 지정하며 목차와 본문 순서를 일치시킵니다. AI 구현 설명에는 실제 추천 결과 화면을, 설계 영역에는 온프레미스·AWS 구성도를 제공합니다.

노후하우의 우리FISA 표기와 전체 상세의 돌아보며 영역은 표시하지 않습니다.
